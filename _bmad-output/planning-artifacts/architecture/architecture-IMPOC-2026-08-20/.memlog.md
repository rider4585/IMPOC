- (decision) AD-17 REDESIGNED on Raviraj's own proposal 2026-08-20, replacing the pure sequence. Barcode value = [minutes since 2026-01-01 Asia/Kolkata: 7 digits][counter within that minute: 5 digits] = 12 digits, zero-padded, digits only. Rationale: uniqueness must not depend on durable state a restore can rewind. A restore takes far longer than a minute, so the minute the system returns in has never issued a label - a printed-but-unscanned sheet stays VALID after a restore instead of having to be discarded. This deletes the boot setval recovery AND the whole post-restore discard procedure from the spine. Arithmetic checked: 7 minute-digits = 10,000,000 minutes = 19 years to ~2045; 5 counter-digits = 100,000 labels/minute; 12 is even so Code 128 subset C still applies at 2 digits/symbol; 12 digits = 121 modules = 0.289mm X-dimension at 35mm, above the ~0.25mm phone-camera decode floor but with less headroom than 10 digits (0.318mm) - Raviraj chose 12 knowingly after the trade-off was stated, and CAP-1's caliper-against-a-physical-print check remains the acceptance test. Rejected seconds granularity (9+1 digits gives only 10 labels/second, so one sheet request spills across seconds) and day granularity (4+6 digits still collides on a same-day restore). Residual risk moves from restore to a BACKWARDS server clock jump (NTP correction, host migration), which is far rarer; units.barcode UNIQUE stops being the primary defence and becomes a genuine last resort. Digit width is no longer freely configurable - it is structurally either 7+3=10 or 7+5=12, and AD-28 holds the choice between those two layouts, not an arbitrary number.
